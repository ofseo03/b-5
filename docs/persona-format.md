# 페르소나 형식 초안 (v0.1)

> 상태: **Claude 초안 → 팀 검토 필요.** 회의 결정사항("형식은 고정, LLM은 내용만 채운다")에 맞춰 작성했다.
> 가입 질문은 [signup-questions.md](signup-questions.md)에 있고, 각 질문이 이 문서의 어느 필드를 채우는지 표시해 두었다.

## 1. 원칙

1. **형식 고정** — 필드 이름·구조·허용 값은 이 문서가 정한다. LLM은 필드를 추가하거나 빼지 않고 값만 채운다.
2. **답변에 근거한 내용만** — 사용자가 말하지 않은 사실(직업, 나이, 사는 곳 등)을 지어내지 않는다. 모르면 `null` 또는 빈 배열.
3. **익명성 우선** — 실명, 연락처, 학교·회사 이름, 구체적 주소처럼 사람을 특정할 수 있는 정보는 페르소나에 넣지 않는다. 답변에 있으면 일반화한다 (예: "OO대 컴공" → "개발 공부").
4. **태그는 짧게** — 태그는 2~6자 정도의 명사·형용사형. 일치율 계산과 프로필 카드 표시에 그대로 쓴다.
5. **최소 항목만** — 이번 버전은 성격, 말투, 취미·관심사, 대화 성향, 매칭 키워드만 둔다. 항목 추가는 "페르소나 업데이트"(부가 기능, 대기)와 함께 다룬다.

## 2. 필드 정의

| 필드 | 타입 | 필수 | 설명 | 채우는 곳 |
|---|---|---|---|---|
| `schema_version` | string | ✅ | 형식 버전. 지금은 `"0.1"` | 시스템 |
| `profile.nickname` | string | ✅ | 사용자가 정한 닉네임 | 가입 화면 |
| `profile.avatar_id` | string | ✅ | 미리 만든 동물 캐릭터 ID (예: `fox_03`) | 가입 화면 |
| `personality.tags` | string[3–5] | ✅ | 성격 태그. 아래 태그 목록에서 우선 선택 | LLM |
| `personality.summary` | string (≤80자) | ✅ | 성격 한두 문장 요약, 3인칭 | LLM |
| `speech_style.formality` | enum | ✅ | `존댓말` / `반말` / `상대따라` | 질문 선택지 |
| `speech_style.tone_tags` | string[2–4] | ✅ | 말투 태그 (예: `차분한`, `장난스러운`) | LLM |
| `speech_style.message_length` | enum | ✅ | `짧게` / `보통` / `길게` | LLM (예시 메시지 길이로 판단) |
| `speech_style.emoji_usage` | enum | ✅ | `안씀` / `가끔` / `자주` | 질문 선택지 |
| `speech_style.habits` | string[0–3] | | 말버릇·자주 쓰는 표현 (예: `ㅋㅋ 자주 씀`, `~요? 로 끝냄`) | LLM |
| `speech_style.sample_messages` | string[1–3] | ✅ | 사용자가 직접 쓴 예시 메시지 원문 (개인정보 제거) | 질문 원문 |
| `hobbies` | object[1–5] | ✅ | 취미 목록, 아래 하위 필드 | LLM |
| `hobbies[].name` | string | ✅ | 취미 이름 (태그형, 예: `영화`) | LLM |
| `hobbies[].detail` | string (≤60자) | | 구체 내용 (예: "SF 영화, 극장에서 혼자 보는 걸 좋아함") | LLM |
| `hobbies[].level` | enum | | `가볍게` / `꾸준히` / `깊게` | LLM |
| `interests` | string[0–8] | | 취미까진 아니지만 관심 있는 주제 태그 | LLM |
| `conversation.likes` | string[1–4] | ✅ | 즐거운 대화 주제·방식 | LLM |
| `conversation.avoid` | string[0–4] | | 피하고 싶은 주제 (페르소나도 이 주제는 피함) | 질문 원문 → LLM |
| `conversation.pace` | enum | | `천천히 알아가기` / `빠르게 친해지기` | 질문 선택지 |
| `relationship.date_style` | string[0–3] | | 선호하는 만남·데이트 형태 태그 (예: `카페`, `전시`, `산책`) | LLM |
| `relationship.values` | string[0–3] | | 관계에서 중요하게 여기는 것 (예: `연락 빈도`, `취미 공유`) | LLM |
| `match_keywords` | string[] | ✅ | 일치율 계산용 명사 키워드. 답변 전처리 결과 + 태그 합집합, 정규화됨 | 전처리 + LLM |
| `meta.source_answer_ids` | string[] | ✅ | 이 페르소나를 만든 가입 답변 ID 목록 | 시스템 |
| `meta.created_at` | string (ISO 8601) | ✅ | 생성 시각 | 시스템 |
| `meta.missing_fields` | string[] | | 답변이 부족해 비어 있는 필드 이름 | LLM |

### 제외한 것

- **MBTI 등 성격 척도** — 회의에서 쓸모없다고 판단.
- **나이·지역·직업** — 매칭 필터로는 필요할 수 있지만 페르소나(대화용 인격)와는 분리한다. 필요하면 별도 `user_profile`로 둔다. → 팀 결정 필요
- **레벨·정보량 점수** — 레벨 기능은 아이디어 후보로만 보관.

## 3. 태그 목록 (초안)

자유 입력 태그는 일치율 계산이 흔들리므로, LLM은 아래 목록에서 **먼저** 고르고 맞는 게 없을 때만 새 태그를 만든다. 새 태그는 로그로 모아 목록 확장에 쓴다.

**성격** — 차분한, 활발한, 호기심많은, 다정한, 솔직한, 유머있는, 신중한, 즉흥적인, 계획적인, 낯가리는, 사교적인, 배려심있는, 독립적인, 감성적인, 이성적인, 긍정적인

**말투** — 차분한, 장난스러운, 친근한, 정중한, 간결한, 수다스러운, 다정한, 직설적인, 리액션많은, 진지한

**취미 (대분류)** — 영화, 드라마, 음악, 공연, 전시, 독서, 게임, 운동, 러닝, 등산, 여행, 캠핑, 요리, 카페, 맛집, 사진, 그림, 반려동물, 개발, 글쓰기, 패션, 춤, 악기, 봉사

## 4. 예시

```json

  "profile": {

    "avatar_id": "fox_03"

    "tags": ["차분한", "호기심많은", "낯가리는"],

  },
  "speech_style": {
    "formality": "상대따라",
    "tone_tags": ["친근한", "리액션많은"],
    "message_length": "보통",
    "emoji_usage": "가끔",
    "habits": ["ㅋㅋ 자주 씀", "질문으로 대화를 이어감"],
    "sample_messages": [
      "이번 주말에 시간 되면 같이 전시 보러 갈래요? 저 보고 싶은 거 생겼어요 ㅋㅋ"
    ]
  },
  "hobbies": [
    { "name": "영화", "detail": "SF 영화를 좋아하고 극장에서 혼자 보는 편", "level": "꾸준히" },

  ],
```

## 5. 생성 프롬프트 (LLM API 공통)

LLM API는 아직 미정이므로, 어느 모델에도 쓸 수 있게 "JSON만 출력" 방식으로 작성했다. 구조화 출력(JSON schema)을 지원하는 API라면 위 표를 JSON Schema로 옮겨 함께 넘긴다.

```text
너는 소개팅 앱의 페르소나 작성기다. 아래 [가입 답변]만 근거로 [형식]에 맞는 JSON을 하나 출력한다.

규칙:
- [형식]의 필드만 사용한다. 필드를 추가하거나 이름을 바꾸지 않는다.
- 답변에 없는 사실은 지어내지 않는다. 근거가 없으면 null 또는 []로 두고 meta.missing_fields에 적는다.
- 실명, 연락처, 학교·회사 이름, 주소 등 사람을 특정할 수 있는 정보는 넣지 않고 일반화한다.
- 태그는 [태그 목록]에서 먼저 고르고, 맞는 것이 없을 때만 2~6자 새 태그를 만든다.
- speech_style.sample_messages는 사용자가 쓴 문장을 그대로 옮기되 개인정보만 지운다.
- match_keywords에는 [전처리 키워드]를 모두 포함하고, 태그 중 명사형인 것을 더한다.
- JSON 외의 텍스트는 출력하지 않는다.

[형식]
{persona_format_json_schema}

[태그 목록]
{tag_list}

[가입 답변]
{answers}

[전처리 키워드]
{extracted_nouns}
```

## 6. 검증 (서버 측)

LLM 출력은 저장 전에 다음을 확인하고, 실패하면 1회 재생성 후 그래도 실패하면 기본값으로 채우고 `missing_fields`에 남긴다.

- JSON 파싱 가능, 필수 필드 존재, enum 값 유효, 배열 길이 범위 준수
- `summary`·`detail` 글자 수 제한
- 개인정보 패턴(전화번호, 이메일, URL 등) 정규식 검사

## 7. 팀이 정해야 할 것

- [ ] 필드 구성 확정 — 특히 `relationship`을 1차 버전에 넣을지
- [ ] 나이·지역 등 매칭 필터용 정보를 받을지, 받는다면 페르소나와 분리 저장할지
- [ ] 태그 목록 확정 및 자유 태그 허용 범위
- [ ] 개인정보 일반화 수준 (지역명, 동네 수준까지?)
- [ ] 말투 학습을 가입 때만 할지, 대화하면서도 갱신할지 (갱신한다면 `speech_style`만 갱신 대상으로 두는 안)
