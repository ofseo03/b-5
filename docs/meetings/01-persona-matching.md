# 회의록 01 — 페르소나 기반 매칭 기본 기능

## Action Items

- [ ] 페르소나 형식(성격, 말투, 취미 등 태그)을 Claude로 초안 작성하고, 팀이 수정한 뒤 그에 맞는 가입 질문도 만들기 (담당자 미정)
  - 초안: [페르소나 형식](../persona-format.md), [가입 질문](../signup-questions.md)
- [ ] 고스팅 기능의 포함 여부와 방식을 더 검토하기 (담당자 미정)

## Decisions

- 페르소나와 대화한 채팅방을 실제 사람과의 대화로 그대로 이어 쓴다
  - 흐름이 자연스럽고, 앞선 대화를 바탕으로 바로 대화할 수 있으며, 새 채팅방으로 가면 어색해지기 때문이다
- "대화하기" 버튼을 항상 켜 두고, 페르소나와 5번 대화를 마칠 때까지 기다리지 않아도 된다
  - 페르소나가 별로면 5번을 다 채울 필요가 없다
- 선택은 24시간 동안 보류할 수 있고, 마감 1시간 전에 알림을 보낸다. 선택하지 않으면 자동으로 "선택 안 함" 처리한다
  - 페르소나 대화 기록은 상대방에게 알림이 가지 않으므로 바로 선택하지 않아도 문제가 없다
- 가입 시 반(半)구조화된 질문으로 페르소나를 만들고, 형식은 고정해 둔다
  - LLM이 매번 정하게 하면 일관되지 않기 때문이다
- 프로필 사진은 미리 만든 동물 캐릭터 중에서 고르게 하고 자유롭게 변경할 수 있게 한다
  - 페르소나는 익명성을 지키기 위한 기술이기 때문이다
- 레벨 기능은 넣지 않고 아이디어 후보로만 보관한다
  - 대화하다 보면 정보량이 느껴지고, 페르소나 대화량도 정해져 있어 굳이 필요 없다는 의견이 모였다
- 가입 후 페르소나 업데이트, 대화 후 피드백 수집 같은 부가 기능은 제외하고 최초 기능만 먼저 만든다
  - 부가 기능이라 먼저 만들어 보고 나중에 추가하는 편이 낫다

## Summary

### 가입과 페르소나 생성

- 가입 시 5~10분의 구조화된 질문으로 관심사, 취미, 말투 등을 파악해 개인별 AI 페르소나를 만든다
  - 답변은 정규식 등으로 전처리해 명사만 뽑고, 이를 일치율 계산에 사용하는 방안이 나왔다
  - 답변이 짧거나 모호하면 꼬리 질문을 최대 2개까지 한다
  - MBTI 같은 척도는 쓸모없다고 보았고, 유사도 방식은 일단 대기로 두었다
- 페르소나 형식은 성격, 말투, 취미 등 최소 항목을 고정하고 LLM이 내용을 채우게 한다
  - 형식과 질문은 둘 다 Claude에게 만들게 한 뒤 팀이 수정한다
- LLM은 직접 만들지 않고 API를 가져와 쓴다
- 일치율 표시 방식(60~100%)은 계산해 본 뒤 차후에 정한다

### 매칭과 채팅 흐름

- 앱을 켜면 AI가 계산한 일치율이 높은 프로필을 보여 주고, 오른쪽 스와이프는 Yes, 왼쪽은 No이다
- Yes를 고르면 상대 페르소나와 채팅하고, 채팅방은 남겨 둔다
  - 기록이 남으면 사용자가 나중에 다시 볼 수 있고 팀도 데이터를 수집할 수 있다
- 채팅방 최대 개수를 두자는 의견이 나왔고 5개 또는 10개가 거론됐다
  - 제한 없이 쓰면 비교할 수 있어 좋다는 반론과 데이터 비용 우려가 맞섰다
- 사람과의 연결 방식
  - 연결 요청을 받는 쪽이 수락 여부를 고르게 하자는 의견과 요청함을 따로 두자는 의견이 있었다
  - 결국 기존 페르소나 채팅방을 이어서 쓰는 쪽으로 의견이 모였다
  - 상대도 페르소나 대화 내용을 볼 수 있고, "영화에 관심 있다는데 어떤 영화 좋아하세요?" 같은 식으로 바로 이어갈 수 있다
- 페르소나가 잘못 학습하거나 사용자가 인격을 꾸며내는 문제는 온라인 소개팅의 한계로 보고 지금은 다루지 않는다
  - 모순 분석 기능은 앱 출시 단계에서 고려한다

### 프로필과 익명성

- 닉네임은 직접 설정하게 하되 개인정보가 드러나지 않도록 사전 고지한다
  - 전화번호 등을 쓰면 업적이나 이스터에그로 활용하자는 농담성 아이디어도 나왔다
- 닉네임 변경 여부는 미정
  - 이름이 바뀌면 이전 채팅 상대를 헷갈릴 수 있다는 우려가 있었다

### 학습량과 레벨

- 정보가 많은 사용자끼리만 매칭하자는 아이디어가 나왔다 (정보가 너무 적으면 신뢰하기 어렵다는 이유). 일단 만들어 보고 판단한다

### 고스팅

- 찬성: 열심히 대화했는데 연락이 끊기면 불이익이 없다
  - 읽고도 답이 없거나 3일 이상 안 읽으면 점수를 조금씩 깎고, 추천에 덜 뜨게 하는 보이지 않는 지표 방식이 나왔다
- 반대: 사람 간 대화나 실제 만남은 팀이 관여할 수 없고 신고와 이의제기 처리가 많아진다

### 피드백과 업데이트 (부가 기능, 대기)

- 페르소나 대화 후 "이 대화는 어떠셨나요?" 같은 피드백 수집
- 나중에 항목(예: 취미)을 추가하면 기존 사용자에게 정보가 없는 문제 → 몇 개월에 한 번 "페르소나 업데이트"를 선택 옵션으로 두는 방안
